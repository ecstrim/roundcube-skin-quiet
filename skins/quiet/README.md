A calm Roundcube skin that extends Elastic. Design: `docs/specs/2026-10-19-quiet-skin-design.md`.

## Install

Requires Roundcube **1.6.x** (developed on 1.6.10, tested on 1.6.20) with the stock `elastic` skin present, because Quiet
declares `"extends": "elastic"` and falls back to Elastic for everything it does not override.

1. Copy the `skins/quiet` folder into your Roundcube's `skins/` directory, next to `skins/elastic`.
   No core patches and no config change are needed.
2. In Roundcube, open Settings > Preferences > User Interface and choose **Quiet** as the skin.
   (Or set `$config['skin'] = 'quiet';` for everyone.)

The built CSS (`styles/*.min.css`) is committed, so there is no build step on the server.

## Dark mode

Quiet uses Elastic's mechanism, so an existing choice carries over. The colour mode is the `colorMode` cookie
(`dark` or `light`); without it, the browser's `prefers-color-scheme` decides. The toggle lives in the account
popover (the round initial at the bottom of the rail). Dark mode puts the class `dark-mode` on `<html>` and every
dark colour in the skin hangs off that class. Mail content (the open message and the compose editor body) stays a
white box in dark mode and is never recoloured.

## Colour schemes

Four colour schemes, each with light and dark values: Lake blue (default), Cobalt, Deep teal and Ink indigo. The
picker is in the account popover (on phones, in the off-canvas menu). The choice is the `quietScheme` cookie
(`cobalt`, `teal` or `indigo`; no cookie means Lake blue), so it is per browser, like dark mode.

Each scheme is a full stylesheet, `styles/scheme-<name>.min.css`, built from `styles/scheme-<name>.less`: the whole
skin with only the colour tokens redefined. An early script in `layout.html` swaps `styles.min.css` for the
variant before the page renders; `quiet.js` swaps it live (page and frames) when a swatch is clicked. To add a
scheme: copy a `scheme-*.less`, add it to the `css` target in the Makefile, to the cookie pattern in `layout.html`,
to `SCHEMES` in `quiet.js`, and give it a swatch button and labels.

## Development

Build CSS from the repo root with `make css` (LESS, via a node container).
Elastic's LESS sources are copied into a git-ignored `skins/elastic/` at build time and are not part of this skin.

Design tokens live in `styles/_variables.less` (`@quiet-*`, each with a `-dark` twin).

The font is IBM Plex Sans, bundled in `fonts/` (latin + latin-ext woff2, weights 400/500/600 and 400 italic,
SIL Open Font License in `fonts/OFL.txt`), with Segoe UI and common Linux UI fonts as fallbacks.

Icons: every Elastic font glyph is redrawn as a stroke icon by `styles/quiet/_glyphs.less`, which is generated by
`dev/glyphs/gen_glyphs.py` from Elastic's compiled CSS (the script's docstring has the commands). Icons come from
Quiet's own set or from Lucide (ISC licence). Hand-tuned icon rules in `styles/quiet/icons.less` load later and win.
A Quiet rule that puts text into an Elastic icon slot (a separator, a "×") must also reset the mask
(`background: none; mask: none`), or the generated icon shape shows instead of the text.

## Templates

`templates/includes/layout.html` is a verbatim copy of Elastic's. Roundcube resolves
`/styles/styles.css` against the skin of the *template that includes it*, so without this
copy every page would load Elastic's CSS. Keep it in sync when Elastic changes, and
extend it only where Quiet needs to.

## Compose folder pane

The compose page has a folder pane on desktop, but Roundcube does not register the `mailboxlist` object on
compose. `compose.js` therefore builds it from the "save sent in" folder select, so it lists writable folders only
(read-only/shared folders are missing) and has no unread counts or quota. It is not shown in the compose popup window.


## Known limitations

Plugin buttons injected into Elastic's `toolbar` container (for example `markasjunk`) are hidden at desktop
widths in this version, because Quiet replaces that toolbar with its own actions. They still show at phone and
tablet widths. The archive plugin is supported (Archive in the list, the reading pane and the multi-select bar).

## Localization

The few labels Roundcube has no equivalent for ("N selected", the selection hint, Archive fallback, "Clear
selection") live in `localization/<lang>.inc` (`"localization": true` in `meta.json`). English and Italian are
included; other languages fall back to English. Add a `<lang>.inc` next to `en_US.inc` to translate them.

## Upgrading Roundcube

Quiet overrides these Elastic templates: `layout` (includes), `menu` (includes), `mail`, `message`, `compose`,
`login` and `watermark`. After a Roundcube update:

1. Diff each of them against the new Elastic (`skins/elastic/templates/...`, `skins/elastic/watermark.html`) and
   carry over what changed: new elements, ids, attributes and scripts. `layout.html` must keep its stylesheet links
   (`styles.css`, `print.css`, `embed.css`), the colour-scheme script and the dark-mode early script.
2. Rebuild the CSS against the new Elastic: `make css RC_TAG=<new image tag>` (default `1.6.20-apache`). This
   re-copies Elastic's LESS from that image into `skins/elastic/` (git-ignored; delete the folder first when the
   tag changed) and rewrites `styles/*.min.css`. Commit the result.
3. Regenerate `styles/quiet/_glyphs.less` with `dev/glyphs/gen_glyphs.py` from the new Elastic (new or renamed
   glyphs show up as unmapped in the file header; add them to its `MAP`), then run `make css` again.
4. Point the dev stack at the new image (`RC_TAG=<tag> make up`), then run `make seed` and `make e2e`.
5. Bump the tested version in "Install" above.
